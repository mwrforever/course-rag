# RAG 课程助手（commerce-customer）

## 一、项目背景

在线教育场景里，课程资料（课件、讲义、表格、截图）散落在各种文档中，学生反复问同类问题，教师答疑成本高；而通用大模型既答不出课程私有内容，又容易编造答案。

本项目是一套企业级**多模态 RAG 课程助手**：把课程资料解析、分块、向量化入库后，学生提问时先理解意图、再检索课程知识、最后让大模型**基于检索到的资料**作答，回答逐字流式返回并附带引用的资料来源；同时通过偏好与情景记忆，让助手在使用中逐渐贴合每个学生的学习习惯。系统同时覆盖 AI 助教对话与课程业务两条主线，配套教师侧的知识库与课程管理后台。

技术栈：Java 17 + Spring Boot 3.5 + Spring AI Alibaba（Agent 图编排）、PostgreSQL / Redis / Milvus / MinIO；
C 端 Next.js 15，B 端 Vue 3.5，pnpm workspace 单仓管理；大模型能力经阿里云百炼（DashScope）接入。

工程规范见 [AGENTS.md](AGENTS.md)，变更记录见 [CHANGELOG.md](CHANGELOG.md)，待办登记见 [TASK.md](TASK.md)。

## 二、启动命令

**环境要求**：JDK 17、Maven 3.9.16、Node 22 + pnpm 9.15.9（经 corepack 提供）、Docker。

### 1. 启动基础设施

```bash
docker compose -f docker-compose.dev.yml up -d
```

拉起 PostgreSQL(5432)、Redis(6379)、MinIO(9002，控制台 9003)、etcd、Milvus(19530)。

### 2. 配置后端环境变量

在 `backend/.env` 中至少填写：

- `DASHSCOPE_API_KEY`：模型调用密钥（必填）
- `MAIL_USERNAME` / `MAIL_PASSWORD`：注册验证码邮件发件账号（使用邮箱注册功能时填写）

其余连接项（PG / Redis / MinIO / Milvus / JWT）均有可用的本地默认值，无需修改。数据库表结构由 Flyway 在后端启动时自动迁移。

### 3. 启动应用

一键启动（推荐，含基础设施）：

```bash
dev.bat all        # Windows cmd
./tools/dev.sh all # Git Bash / Linux / macOS
```

分步与运维子命令（两端脚本一致）：`infra` 仅基础设施、`backend` 仅后端、`c` 仅 C 端、`b` 仅 B 端、`status` 查看状态、`stop` 停止进程、`down` 停止并关闭容器、`logs` 查看日志、`envs` 查看注入的环境变量。

也可手动分别启动：

```bash
cd backend && mvn spring-boot:run     # 后端服务 :8080
cd student-frontend && pnpm dev       # C 端学生端 :5000
cd frontend && pnpm dev               # B 端管理端 :5001
pnpm dev                              # 仓库根目录：并行拉起两个前端
```

### 4. 校验命令

```bash
mvn -f backend/pom.xml verify                 # 后端：格式 / 规范 / 静态检查 / 单测 / 覆盖率门禁
pnpm lint && pnpm typecheck && pnpm test:cov && pnpm e2e   # 前端（两个 app 各自执行）
pnpm check:cross-imports                      # 双前端禁止互相引用断言
```

## 三、功能设计架构

### 3.1 整体结构

```
C 端学生学习空间（课程橱窗 · 我的课程 · AI 助教对话）
B 端教师/管理后台（知识库 · 文档与分块 · 课程 · 学生 · 数据看板）
                    │
        后端服务（业务接口 + Agent 图编排）
        ├─ 对话链路：意图理解 → 知识检索 → 回答生成，全程流式下发
        ├─ 知识入库：多模态解析 → 分块 → 向量化 → 入库
        ├─ 记忆体系：偏好记忆 + 情景记忆
        └─ 业务域：课程 / 报名 / 用户 / 看板
                    │
PostgreSQL（业务数据、会话与消息、图状态）· Redis（任务队列、缓存）
Milvus（向量检索）· MinIO（对象存储，文档与图片）
```

### 3.2 RAG 检索链路

**理解 → 检索 → 生成** 三段式，检索由意图驱动、检索结果决定回答依据：

1. **意图理解**：先判断学生的提问属于「课程知识提问 / 闲聊 / 无法归类」——只有知识提问才走检索，闲聊直接回答，避免答非所问地硬塞资料。对知识提问进一步做查询改写，把口语化提问改写成利于检索的表达，并抽取课程、资料范围等筛选条件用于收窄检索范围。
2. **混合检索**：改写后的查询同时走**语义向量检索**与**关键词检索**两条通路召回课程片段，两路结果融合排序后由重排模型精选，再按相关度阈值过滤，得到真正相关的一小批资料。
3. **上下文组装与生成**：把精选片段连同学生的偏好一起注入系统提示，大模型**只依据这些资料**作答并说明出处；资料不足以回答时明确告知，而不是编造。回答逐字流式返回，同时把引用的课程片段来源推给前端展示。
4. **多轮与跨会话**：多轮对话携带最近上下文与历史摘要，长会话自动压缩；学生的稳定偏好与过往问答经验（情景记忆）在回答前自动召回注入，跨会话生效。

### 3.3 对话与断线恢复设计

围绕「**生成不因前端断开而中断，回来后能接着看**」设计：

- **流式过程可视化**：回答逐字推送，思考过程、检索来源、工具调用与阶段进度同步下发，前端以时间轴还原完整推理过程。
- **断线自动恢复**：网络抖动或页面刷新后，客户端凭运行标识自动重连，服务端按已接收进度**补发遗漏内容**再接续实时输出，无需重新提问。
- **切走再切回**：离开会话**不打断生成**，回到会话即自动续接进行中的回答；同一用户可同时开启多个会话并行问答，互不干扰。
- **断开不禁生成**：等待期间关闭页面，生成仍在服务端继续执行并完整落库，回到会话仍可看到完整回答。
- **主动停止**：随时可停止生成，已输出的内容保留在会话中，并继续作为下一轮的上下文。
- **失败自愈**：生成超时或断流时自动重试；多次无有效产出才向用户报错，并给出重新生成入口。
- **会话内串行、会话间并行**：同一会话同时只允许一次生成，避免上下文错乱；跨会话并发互不影响。异常滞留的会话会被自动回收解锁。

### 3.4 知识入库（ETL）

- 支持课件、文档、表格、图片等多形态资料的解析入库；图片生成文字描述后参与检索，表格按结构化方式切分，避免跨页断裂。
- 分块与向量化后可查看分块内容并人工校正，教师侧边改边见效。
- 学生上传的图片/文档**不进入知识库**，只在本次会话内参与回答，用完即散。

### 3.5 记忆体系

- **偏好记忆**：从对话中提取学生稳定的学习偏好，达到一定置信度后生效，在后续回答中自动注入。
- **情景记忆**：沉淀历史问答经验（问过什么、结论是什么、是否有用），跨会话召回，让助手"记得"此前的交流。
- 两类记忆均按用户隔离，只服务于本人。

### 3.6 双端功能一览

| 端 | 功能 |
|----|------|
| C 端学生端 | AI 课程助手（多会话并行、附件提问、思考与来源时间轴、编辑重发 / 重新生成 / 停止 / 复制）、课程中心与课程详情、课程购买与报名、我的课程、个人中心、邮箱验证码注册登录 |
| B 端管理端 | 数据看板、知识库管理、文档上传与解析、分块查看与校正、课程与章节排课管理、学生与教师管理、会话管理、反馈管理、账号安全（登录记录 / 令牌黑名单） |

## 四、示例数据（docs/data）
