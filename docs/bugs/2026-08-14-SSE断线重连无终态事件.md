# SSE 断线重连无终态事件：run 已完成时重连，前端永久"生成中"

- **风险类别**：跨端兼容 / 流完整性（SSE 无 end 终态，前端状态机卡死）
- **严重度**：P1（确定性触发，无需极端条件）
- **变更范围**：未提交工作区全部新增代码

## 证据

1. `ChatController.java:221-257`（reconnect 流程）：
   - `bridge.replay(runId, lastEventId, emitter)` → run 已结束时 ring 已被 Worker `removeRing` 移除 → 返回 false；
   - `replayFromPg(runId, ...)` → run 已完成且消息已落库 → 返回 true；
   - 继续执行 `bridge.subscribe(runId, emitter)`。

2. `MemoryStreamBridge.java:69-76`（subscribe 对 ring 不存在的情况）：
   ```java
   public void subscribe(String runId, SseEmitter emitter) {
       Ring ring = rings.get(runId);
       if (ring == null) {
           log.warn("subscribe 失败: runId={} 的 ring 不存在", runId);
           return;          // emitter 不注册、不 complete
       }
       ring.subscribe(emitter);
   }
   ```

3. `ChatController.java:245-246`：`bridge.subscribe` 后无条件 `startHeartbeat(emitter)`，每 15s 发送 `:heartbeat` 注释行保活（SseEmitter 超时 30 分钟）。

## 触发路径与影响

用户在 run 执行中断线 → run 在断线期间完成（Worker finally 中 `removeRing` 触发 `Ring.close()` complete 旧 emitter）→ 用户重连：PG 回放成功拿到历史消息，但 subscribe 静默失败（ring 已移除），新 emitter 永远不会收到 `end` 事件；心跳注释行持续保活使前端"30s 无事件超时"提示也永不触发 → **UI 永久停留在"生成中"直到 30 分钟 emitter 超时**。

## 建议修复方向

reconnect 中若 `bridge.replay` 失败但 PG 回放成功，应主动查询 run 终态（COMPLETED/CANCELLED/ERROR）：已终态则回放后推送 `end` 事件并 `emitter.complete()`；仅活跃 run 才继续 subscribe + 心跳。

## 附：关联竞态（B5）

`ChatController.java:226` replay 与 `:252` subscribe 之间存在时间窗：Worker 在两者之间 push 的事件（seq > replay 时读取的 head）既不在回放范围、也到不了尚未注册的 emitter → 断线重连时窗口内事件（delta/tool_result/end）永久丢失，客户端按 lastEventId 续传出现序号空洞。chat() 端点注释明确"先 subscribe 再入队不丢事件"，reconnect 未采用同序。窗口极小（毫秒级）但语义上必然存在。
