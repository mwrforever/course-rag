# 教师越权集群：文档改名/下载/跨库上传 + 用户管理与课程详情无归属校验

- **风险类别**：权限绕过（水平越权/提权/信息泄露）
- **严重度**：P0（在 `2026-08-14-权限机制断裂` 修复后立即暴露；当前因 403 被掩盖）
- **变更范围**：未提交工作区全部新增代码

> 注：本仓库三份设计文档（db-schema.md C4/C7 权限矩阵 = "✅ 自己"）明确要求 TEACHER 只能操作自己的资源，以下实现全部违反。

## 证据（8 项）

### 1. 文档改名越权 —— `DocumentService.java:159-171`
```java
public void update(Long id, String title, Long operatorId) {
    Document doc = documentMapper.selectById(id);   // 仅判存在
    // operatorId 从未被使用，无 checkOwnership 调用
    documentMapper.update(null, wrapper);            // 直接更新
}
```
同文件 delete/reparse（:182-251）有 `checkOwnership`，update 缺失，同一模块不一致。

### 2. 文档下载越权 —— `DocumentService.java:259-268`
```java
public InputStream download(Long id) {
    Document doc = documentMapper.selectById(id);   // 无任何权限参数
```
控制器 `AdminDocumentController.java:184-196`（C7 下载端点）仅角色级 `@PreAuthorize`。任意 TEACHER 可下载任意文档的 MinIO 原始文件。

### 3. 跨知识库上传 —— `DocumentService.java:74-96`
```java
KnowledgeBase kb = knowledgeBaseMapper.selectById(kbId);  // 仅判存在
if (kb == null) { throw ...; }
// 不校验 kb.created_by == createdBy
```
TEACHER A 传 B 的知识库 kbId → 文件进入 B 的知识库并触发 ETL 索引，污染他人知识库。

### 4. 教师可操作任意学生 —— `SysUserService.java:272-289`
```java
private void checkTeacherPermission(SysUser targetUser, Long currentUserId) {
    if (UserRole.TEACHER.name().equals(operator.getRole())) {
        if (!UserRole.STUDENT.name().equals(targetUser.getRole())) {   // 只查角色，不查创建关系
            throw ...;
        }
    }
}
```
且 `V6__full_schema_v5.sql:96-106` 的 `sys_user` 表**根本没有 created_by 列**，"教师只能操作自己创建的学生"（SysUserService.java:29 类注释）在数据结构上不可实现。任意 TEACHER 可对任意 STUDENT 重置密码（接管账号，`resetPassword:174-189`）、禁用（`updateStatus:200-224`）、删除（`delete:234-267`）。

### 5. 创建用户无角色限制 —— `SysUserService.java:63-97` + `CreateUserRequest.java:13-14`
`create()` 无任何调用者角色校验；`CreateUserRequest.role` 仅 `@NotBlank` 无枚举校验。TEACHER 可创建 TEACHER 角色账号（扩权），role 可传任意字符串。

### 6. 用户列表/详情教师无过滤 —— `AdminUserController.java:47-73` + `SysUserService.java:102-108,127-140`
`list()`/`get()` 直接分页/查询全部用户，无教师归属过滤（`checkTeacherPermission` 仅在写操作调用）。任意教师可枚举全部用户（含其他教师与超管的用户名/显示名）。

### 7. 课程详情无归属校验 —— `AdminCourseController.java:82-89`
```java
@GetMapping("/{id}")
public ApiResponse<CourseDTO> detail(@PathVariable Long id) {
    CourseInfo course = courseService.findById(id);   // 无 ownership 参数
    return ApiResponse.ok(courseService.toDTO(course, true));   // 含内容+排期+老师 4 Tab 全量
}
```
对比同控制器 list（:52-54）有 createdBy 过滤、update（E7/E9）调 `checkOwnership`，detail 缺失。任意教师可查看任意课程完整内容。

### 8. 反馈无归属校验 + user_id 缺失 —— `FeedbackController.java:40-47` + `V6__full_schema_v5.sql:306-314`
`create` 完全不读取当前用户（HttpServletRequest 参数未用），信任 body 的 sessionId/messageId；`user_feedback` 表无 user_id 列（与 `backend-design.md:687` 约定 `UNIQUE(user_id, message_id)` 冲突）。任意学生可跨用户伪造赞/踩，污染 B 端统计。

## 建议修复方向

- update/download 补 `checkOwnership`（与 delete/reparse 一致）；
- upload 校验 `kb.createdBy == createdBy`；
- `sys_user` 加 `created_by` 列并迁移既有数据，`checkTeacherPermission` 校验创建关系；
- `CreateUserRequest.role` 加 `@Pattern` 枚举校验 + 教师仅可创建 STUDENT；
- detail 传入 userId/role 过滤；
- `user_feedback` 表补 user_id 列（走新 Flyway 迁移，禁止改 V6），create 取当前登录用户。
