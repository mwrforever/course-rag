# 跨端契约不一致：分片编辑接口方法与前端设计文档冲突

- **风险类别**：跨端兼容（前端按设计文档落地即 404/405/参数失效）
- **严重度**：P2（前端尚未实现，落地时必然踩坑）
- **变更范围**：未提交工作区全部新增代码

> 依据 AGENTS.md 工程宪法："禁止单方面变更三文档间的接口契约（前端 ↔ SSE 10 事件 ↔ DB）"，`docs/plans/2026-07-16-frontend-design.md` 是前端契约唯一真相源。

## 证据（实现 vs 前端设计文档）

| # | 实现 | 前端设计文档 |
|---|------|-------------|
| 1 | `AdminChunkController.java:76` `PUT /{id}/content` | frontend-design.md:933 `PUT /api/v1/admin/chunks/{id}`（路径不同 → 404） |
| 2 | `AdminChunkController.java:122` `@PatchMapping("/batch-corrected")` | frontend-design.md:926 `POST /api/v1/admin/chunks/batch-corrected`（方法不同 → 405） |
| 3 | `AdminDocumentController.java:100-113` 文档列表仅 kbId/page/size | frontend-design.md:871 要求 `status/q/sort` 筛选参数（实现不支持 → 参数被忽略） |
| 4 | 无 dashboard 统计实现（仅 `GET /api/v1/admin/feedbacks/stats`，intentType 分组、无 period 维度） | frontend-design.md:783-786 `GET /api/v1/admin/dashboard/stats`、`/admin/feedback/stats?period=today`、`/admin/feedback/trend?days=7`（三个接口全部 404） |
| 5 | RESTful 扁平路径（如 `/admin/documents/{id}/download`） | db-schema.md:1118/1126 `knowledge-bases/{kbId}/documents`、`documents/{docId}/chunks` 层级路径 |

## 影响

前端按设计文档落地后：分片编辑保存 404、批量标记已修正 405、文档列表筛选参数静默失效、管理首页 dashboard 三个接口全部 404。

**补充说明**：后端设计文档（backend-design.md §八）与前端设计文档（frontend-design.md）本身也存在不一致（如统计接口形态），本次仅列出"实现 ↔ 前端文档"之间无歧义的冲突点。修复前建议先对齐三份文档再改实现。

## 其他跨端观察（证据不足，未列为独立 bug）

- `SseEventTransformer.java:163,198`：tool_call/tool_result 关联字段用 camelCase `toolCallId`，设计文档 §3.2 写 `tool_call_id`（snake_case）；前端未实现，无法定论，但违反"禁止单方面变更契约"。
- `ChatRequestWorker.java:712-714`：取消用 `end` 事件 + payload `status:"CANCELLED"` 表达，设计文档 §3.4 说发独立 `cancelled` 事件；前端 10 事件表无 `cancelled`，需读 payload 区分，契约未明示。
- `SseEventTransformer.java:199`：tool_result 恒为 `"status":"success"`，工具失败无 error 状态位，前端 ToolCallCard 无法渲染失败态。
