# ETL 幂等性与分片更新一致性：重复入库、误标 INDEXED、流泄漏

- **风险类别**：数据一致性 + 资源泄漏
- **严重度**：P2（触发依赖并发/故障时序，但机制确定）
- **变更范围**：未提交工作区全部新增代码

## Bug 1：ETL 无状态守卫，重复执行重复入库（C9）

### 证据
`EtlPipeline.java:98-109` `process()`：
```java
public void process(Long docId) {
    try {
        parseDocument(docId);     // 无 parse_status 检查
        chunkDocument(docId);     // 直接 insert 全新雪花 ID 的 chunk
        embedAndIndex(docId);
    } catch ...
}
```
`DocumentService.reparse`（:223-251）与 `upload`（:101-102）都可触发 `etlPool.execute(() -> etlPipeline.process(id))`，无任何"正在执行"互斥或状态守卫。`embedAndIndex`（`EtlPipeline.java:274-280`）每个 chunk 独立 try/catch `continue`，循环结束后**无条件** `updateDocStatus(docId, "INDEXED")`。

### 影响
- ETL 执行中再次触发（重复点击/并发请求）→ 并发两轮 process → PG/Milvus 分片重复；
- embedding 部分失败时文档误标 INDEXED，部分 chunk 无向量导致检索漏召回。

## Bug 2：chunk 内容更新 PG 与 Milvus 分裂（C10）

### 证据
`DocumentChunkService.java:127-144` `updateContent`：先更新 PG content（:134-139）→ `etlPipeline.reEmbedAndUpsert(id)`（:142）。而 `EtlPipeline.java:293-317`：
```java
float[] vector = embeddingModel.embed(chunk.getContent());   // 失败抛异常上抛
...
deleteFromMilvusByChunkId(...);   // :360-371 内部吞异常
insertToMilvus(...);              // :424-431 内部吞异常
```

### 影响
embedding API 故障时保存分片内容 → PG 为新内容、Milvus 为旧向量；Milvus 删除/插入失败被吞 → PG 新内容 + Milvus 旧内容，检索返回与库内不一致的内容。

## Bug 3：Tika 解析异常时输入流未关闭（C14）

### 证据
`EtlPipeline.java:130-138`：
```java
InputStream inputStream = minioStorageService.downloadFile(doc.getSourcePath());
BodyContentHandler handler = new BodyContentHandler(TIKA_WRITE_LIMIT);
...
parser.parse(inputStream, handler, metadata, context);   // 抛异常（不支持类型/损坏文件）
inputStream.close();                                      // 不执行
```

### 影响
上传任意扩展名文件触发 ETL → 解析失败路径反复泄漏 MinIO GetObject 文件句柄。（注：`AdminDocumentController.java:213-219` 对任意扩展名放行，无白名单；`EtlProperties.maxFileSizeMb` 配置（`EtlProperties.java:28`，application.yml:135 =100）**全仓库无引用**——死配置，实际仅靠 servlet multipart 100MB 兜底。见 C15。）

## 建议修复方向

- `process()` 入口检查 `parse_status`（PENDING/FAILED 才执行），或用 docId 分布式锁互斥；
- `embedAndIndex` 部分失败时标 FAILED 而非 INDEXED；
- `updateContent` 失败时回滚 PG content 或标记补偿重试；
- `parseDocument` 用 try-with-resources 包裹 inputStream；
- 补文件类型白名单并引用 maxFileSizeMb 配置。
