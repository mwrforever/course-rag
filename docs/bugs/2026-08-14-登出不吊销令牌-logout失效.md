# 登出不吊销令牌：logout 端点被拦截器排除，黑名单吊销分支永不执行

- **风险类别**：权限绕过（会话撤销失效，安全路径）
- **严重度**：P1
- **变更范围**：未提交工作区全部新增代码

## 证据

1. `AuthConfig.java:26-28`：`/api/v1/auth/**` 被排除在 AuthInterceptor 之外：
   ```java
   registry.addInterceptor(authInterceptor)
           .addPathPatterns("/api/v1/**")
           .excludePathPatterns("/api/v1/auth/**", "/api/v1/public/**");
   ```

2. `AuthController.java:236-261`：logout 依赖拦截器注入的 attribute：
   ```java
   @PostMapping("/logout")
   public ApiResponse<Void> logout(HttpServletRequest httpRequest, HttpServletResponse httpResponse) {
       Long userId = (Long) httpRequest.getAttribute(AuthInterceptor.ATTR_USER_ID);
       String jti = (String) httpRequest.getAttribute(AuthInterceptor.ATTR_JTI);

       if (userId != null && jti != null) {      // 恒为 null → 分支永不执行
           deviceKickService.addToBlacklist(...);
           revokeLoginRecord(userId, jti);
       }
       clearCookie(httpResponse);                // 只清 cookie
       return ApiResponse.ok();
   }
   ```
   `AuthInterceptor.java:86-88` 确认这两个 attribute 仅由拦截器在 preHandle 注入。

## 触发路径与影响

用户点击登出 → 仅清除 cookie，Access Token 未入黑名单（`sys_token_blacklist` 无记录）、`sys_login_record` 未置 REVOKED。在 AT 剩余有效期（默认 accessTokenExpiry，秒级配置）内 token 仍可调用所有接口。若 cookie/token 被窃取（XSS、日志泄露），用户登出操作无法撤销令牌，且审计记录失真。

## 建议修复方向

logout 从 `Authorization` header 提取 token（不依赖拦截器 attribute），自行解析 jti/userId 后走黑名单 + login_record REVOKED 流程；或将该端点移出排除列表（此时需在拦截器内放行无 token 场景）。
