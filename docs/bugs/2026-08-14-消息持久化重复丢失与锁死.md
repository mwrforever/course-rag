# 消息持久化缺陷：多轮历史全量重复 + 异常路径消息丢失 + XADD 失败锁死会话

- **风险类别**：数据丢失/重复（随轮次指数增长）+ 运行错误（会话永久锁死）
- **严重度**：P0（B3 确定性触发；B7 故障触发即锁死）
- **变更范围**：未提交工作区全部新增代码

## Bug 1：多轮会话消息重复持久化（B3）

### 证据
`ChatRequestWorker.java:516-559` `persistMessages` 遍历 `lastOutput.state().value("messages")` 的**全部**消息：
```java
if (lastOutput != null && lastOutput.state() != null) {
    Optional<Object> messagesOpt = lastOutput.state().value("messages");
    if (messagesOpt.isPresent() && messagesOpt.get() instanceof List<?> rawList) {
        for (Object item : rawList) {
            if (item instanceof Message msg) {
                if (msg instanceof UserMessage) { continue; }   // 仅跳过用户消息
                List<ChatMessage> converted = toChatMessages(msg, runId, sessionId);
                ...
```
messages channel 为 AppendStrategy + checkpoint（`threadId=sessionId`，`ChatRequestWorker.java:333-336`）跨 run 累积完整历史；`toChatMessages`（:613-679）对每个 AssistantMessage/ToolResponseMessage 生成新记录。测试 `ChatRequestWorkerTest.java:193` 用 `state() → null` 规避了此路径。

### 触发路径与影响
会话第 2 轮起，每轮把前几轮的全部 ASSISTANT/THINKING/TOOL_CALL/TOOL_RESULT 记录以**新的 runId** 再次批量 INSERT → 历史回放（`findBySessionId`）、管理端会话详情全部重复，且每轮翻倍增长（第 N 轮累计插入 O(N²) 条）。

## Bug 2：blockLast 超时/同步异常路径无 ERROR 事件、消息不落库（B6）

### 证据
`ChatRequestWorker.java:401-408`：
```java
} catch (Exception e) {
    log.error("processRequest 致命错误 runId={}", runId, e);
    errored.set(true);
    try { chatRunService.updateStatus(runId, "ERROR"); } catch ...
    // 不推 ERROR SSE 事件、不调 persistMessages
}
finally {
    bridge.removeRing(runIdStr);   // Ring.close() 直接 complete 订阅者，无终态事件
    ...
}
```
`blockLast(Duration.ofMinutes(5))`（:399）超时抛 `TimeoutException` 走此路径（图执行 >5min 或 `compiledGraph.stream` 同步抛异常）。

### 触发路径与影响
前端流在无 `end`/`error` 终态事件下被 complete（渲染器显示中断）；用户消息与部分助手消息未入库——断线重连 PG 降级无数据可回放。

## Bug 3：XADD 失败 → QUEUED run 永久残留锁死会话（B7）

### 证据
`ChatController.java:166-175`（顺序：createRing → subscribe → XADD，XADD 前无 try/catch 清理）：
```java
bridge.createRing(runId);
bridge.subscribe(runId, emitter);
Map<String, String> message = Map.of(...);
redisTemplate.opsForStream().add(streamProperties.requestStream(), message);   // 异常 → 500，无任何清理
```
`ChatRunService.createRun`（:45-60）已先行落库 `status=QUEUED`；`V6__full_schema_v5.sql:274`：
```sql
CREATE UNIQUE INDEX uniq_active_run_per_session ON chat_run(session_id) WHERE status IN ('QUEUED', 'ACTIVE') AND deleted = 0;
```

### 触发路径与影响
Redis 抖动时发起对话 → 接口 500，但 QUEUED 行已落库；Redis Stream 中无该消息 → Worker 永不处理 → 部分唯一索引**永久阻塞该 session 的所有后续对话**（无超时回收机制），且 `MemoryStreamBridge.rings` 中该 runId 的 Ring 永不移除（`removeRing` 仅在 Worker finally 调用）——内存 map 累积泄漏。

## 建议修复方向

- B3：persistMessages 只持久化"本轮新增"的消息（按最后 checkpoint 消息数截取，或持久化前先按 sessionId+runId 去重）；
- B6：外层 catch 补推 ERROR 事件 + 持久化已收集消息；
- B7：XADD 包 try/catch，失败时回滚 run 状态（置 ERROR/CANCELLED）并 `bridge.removeRing`；或对 QUEUED 超时巡检回收。
