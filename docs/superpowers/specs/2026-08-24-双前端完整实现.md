## 2. 工程骨架与环境（G4/G5 补全）

### 2.1 Monorepo 结构

```
commerce-customer/
├── backend/                 # 既有（不动）
├── student-frontend/        # C 端（Next.js 15 + TS）
├── frontend/                # B 端（Vue 3.5+ + Vite + TS）
├── pnpm-workspace.yaml      # packages: [student-frontend, frontend]
└── package.json             # 聚合脚本（pnpm -r --filter 或 --parallel）
```

- 聚合脚本：`dev`（两端并行 dev）、`build`、`test`（两端 vitest run）、`lint`、`e2e`（两端 playwright test）、`format`。
- **禁共享包/跨引用**（宪法级约束，CI 用 dependency-cruiser 或 grep 断言：`frontend/src` 不得 import `student-frontend`，反之亦然）。

### 2.2 环境变量与网络（G4 补全）

- **dev 一律走同源 proxy**（推荐路径，零 CORS、零 env）：
  - C 端 `next.config.ts` rewrites：`/api/v1/:path*` → `http://localhost:8080/api/v1/:path*`；
  - B 端 `vite.config.ts` server.proxy：`/api` → `http://localhost:8080`（rewrite 保持路径）。
  - 前端代码 API base 恒为 `/api/v1`（同源相对路径），**不引入任何 NEXT_PUBLIC_/VITE_ 环境变量**（YAGNI；生产部署时由反代承担同源映射）。
- **封面图（MinIO）**：C 端 `next.config.ts` images.remotePatterns 配 `http://localhost:9000`（dev）；组件层 `onError` 兜底 category 渐变占位（设计 §1.5.1），**不依赖 MinIO 桶公开性**。B 端直接 `<img>` + 同款 onError 兜底。
- **B 端 dev 端口必须 5173**（CORS 白名单生效值；走 proxy 后此约束降级为约定）。

## 3. 前端测试工程（G1/G3 补全，审核阻断项）

### 3.1 单元/组件测试（Vitest）

| 端 | 框架 | 核心 100% 覆盖目标（宪法 6.4 界定：状态机/对外协议/鉴权路径） | 非核心 ≥80% |
|---|---|---|---|
| C 端 | Vitest + @testing-library/react + jsdom | `useChatStream` reducer（10 事件全分支）、SSE 解析器（帧格式/heartbeat/id 行/残包）、api client（401 单飞刷新/重放/失败登出）、附件前置校验 | 组件/页面/hook 其余 |
| B 端 | Vitest + @testing-library/vue + jsdom | auth store（刷新单飞/登出）、api client（同上）、ETL 轮询 composable（非终态 5s/终态停）、权限路由守卫 | 组件/页面/store 其余 |

- 覆盖率工具 `@vitest/coverage-v8`； thresholds：全局 lines ≥80%，核心文件（上述清单）lines 100%（coverage 配 include 精确圈定核心文件）。
- 组件测试策略：容器组件（页面）不写重度交互测试（E2E 承担），纯展示组件（CourseCard/Badge/状态徽章）写渲染断言；`thinking 卡折叠`等交互用 Testing Library 用户事件。

### 3.2 E2E（Playwright，两端各自独立目录，TASK.md §2 对齐）

**总方针：route-mock 模式**——E2E 不依赖真实后端（LLM 输出不可控 + CI 需全套中间件不可行）；后端链路已有 Testcontainers 集成测试（Auth/ChatFlow/Security 9 用例）覆盖。Playwright `page.route('**/api/v1/**')` 拦截并 fulfill 预录响应。

目录：
```
student-frontend/e2e/    # C 端 E2E（独立 playwright.config.ts，webServer 起 next dev）
frontend/e2e/            # B 端 E2E（独立 playwright.config.ts，webServer 起 vite dev）
```

**C 端 E2E 用例矩阵**（SSE 10 事件**逐类断言**，TASK.md §2 硬性要求）：

| 用例组 | 断言要点 |
|---|---|
| auth 流 | 登录成功跳首页（mock login 200 + cookie）；错误凭据 401 Alert；未登录访问 /chat 重定向 /login |
| 首页/课程 | J1 mock 渲染课程卡网格；空态引导；搜索/筛选本地行为 |
| SSE-happy | route fulfill `text/event-stream` 逐帧推：metadata→thinking→thinking_end→delta×N→tool_call→tool_result→sources→end；断言：思考卡出现并折叠、正文流式渲染、来源卡渲染（score 置信条）、sessionId=null 时 URL replace、end 后操作栏出现 |
| SSE-事件逐类 | 每类事件单独一个最小用例（10 个）：单推该事件断言对应 DOM（metadata=消息槽+model 徽标；heartbeat=无 DOM 变化但连接保活计时器重置→通过后续 delta 仍接收间接断言；error=横幅；等） |
| SSE-cancel | mock cancel 200 + 推 end{status:CANCELLED}：停止按钮点击→按钮 morph→「已停止生成」后缀→反馈栏不出现 |
| SSE-409 | 第二次发送 mock 409：toast「当前会话正在回答中」+ 输入保持禁用 |
| SSE-reconnect | delta 中途断流（route abort）→ 重连请求携带 lastEventId 断言（route 请求数验参）→ 续流渲染 |
| SSE-REPLAY_FAILED | reconnect fulfill error{code:REPLAY_FAILED}：「会话历史不可用」+ 重新提问引导 |
| 409 删除 | /sessions 删除按钮 mock 409「会话正在对话中」toast |
| 附件 | 超限文件（11 个/超大）前端即拒（无网络请求断言）；合法文件 chips 上传 mock |
| 反馈 | end{messageId} 后点赞→ POST /student/feedbacks 请求体断言 {sessionId,messageId,isLiked} |

## 4. Lint / Format / pre-commit（G2 补全）

- 两端各配 **ESLint flat config**（`eslint.config.js`）+ **Prettier**（`.prettierrc.json`，两端内容可相同但文件独立——配置文件复制不违反禁共享包约束）。
  - C 端：`eslint-config-next`（含 React/hooks 规则）+ `@typescript-eslint`；B 端：`eslint-plugin-vue`（flat/recommended）+ `@typescript-eslint`。
  - 共同规则：`no-console: error`（除允许清单）、`@typescript-eslint/no-explicit-any: error`、unused-imports。
- **pre-commit 接入**（根 `.pre-commit-config.yaml` 增两个 local hook）：
  - `frontend-lint-c`：`cd student-frontend && pnpm exec eslint --cache . && pnpm exec prettier --check .`
  - `frontend-lint-b`：`cd frontend && ...同上`
  - `stages: [pre-commit]`；文件过滤（files 正则限定各自目录），未变更端跳过。
- **CI 前端 job 见 §5**。宪法 §八红线：lint/format/测试不过不得合入。

## 5. CI 集成（.github/workflows/ci.yml 增量）

```
jobs:
  backend（既有，不动：verify 全门禁）
  frontend:            # 新增
    steps: pnpm install --frozen-lockfile
          → pnpm -r lint（两端 eslint+prettier check）
          → pnpm -r typecheck（tsc --noEmit）
          → pnpm -r test:cov（vitest run --coverage，阈值 §3.1）
  e2e:                 # 新增，needs: [frontend]
    steps: pnpm install
          → pnpm -r exec playwright install --with-deps chromium
          → pnpm -r e2e（两端 webServer 自起 dev server，route-mock 无需后端）
```

- pnpm lockfile 提交入库（`pnpm-lock.yaml`）。
- e2e job 与 backend job 并行（互不依赖）；PR 合并检查 = backend + frontend + e2e 三绿。
