### SAA 1.1.2.0 框架坑（源码实锤，勿重复踩）

- **PostgresSaver 自动建表非幂等**：`initTable` 的 CREATE INDEX 无 IF NOT EXISTS，`createTables(true)` 二次启动必炸。正确做法：`createTables(false)`，checkpoint DDL 由 `V7__checkpoint_tables.sql` 管理（表名 `GraphThread`/`GraphCheckpoint` 必须与框架 SQL 完全一致）
- **ReactAgent 工具方法必须标 `@Tool`**，`MethodToolCallbackProvider` 强校验
- **`ReactAgent.asNode` 的节点 id = agent name**：`addNode(id, reactAgent.asNode(...))` 的 id 必须与 `.name(...)` 一致
- 图状态内置策略**仅 2 种**：ReplaceStrategy + AppendStrategy；key 名 `messages` 必须 AppendStrategy
- **无 maxIterations 常量**，循环上限用 `ModelCallLimitHook(runLimit=15)`
- Hook 的 AFTER_MODEL **逆序执行**：注册越晚越先跑
- SM(base) 不落 messages/checkpoint（ModelRequest.systemMessage 独立字段）；SAA 不自动合并多条 SM（自研 CoalescingInterceptor）
- **新增（spec §3.3 源码实锤）**：MessagesModelHook.beforeModel 返回的 messages 以 ReplaceAllWith **写回 state 落 checkpoint**——瞬时注入必须用 ModelInterceptor；`ModelRequest.context` 来自 `RunnableConfig.metadata`（GraphRunner 单一实例贯穿全图，可作图节点 → interceptor 的传递通道）

### 数据层约定（已修正）

- 所有业务表 `id BIGINT` 雪花 + `deleted BIGINT` 软删（0=未删，非 0=时间戳）
- Flyway：`V6__full_schema_v5.sql`=15 业务表+55 索引；`V7__checkpoint_tables.sql`=SAA checkpoint；新增表必须新版本迁移，禁止改已执行迁移；S1 落地新增 V8
- Milvus：`knowledge_chunks` 的 `collection_type` 意图路由**已废弃**（spec §2）；过滤字段改为 content_type/course_id/sha256（spec §3/§4，需 drop 重建 collection）；Episodic 记忆独立 collection `memory_chunks`（spec §8）
- Redis 仅 SSE 流缓冲 + 认证执法层（黑名单/设备互踢），不存 checkpoint、不存上下文
- MyBatis-Plus 配了 `PaginationInnerInterceptor(maxLimit=2000)`，查询必带分页
- S1 新增表：`user_preference` / `user_episodic_memory`（spec §7/§8）；`chat_run` / `chat_message` 加 `attachments_json`（spec §5.1）
