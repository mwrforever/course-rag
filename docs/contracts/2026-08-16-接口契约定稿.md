# 接口契约定稿（2026-08-16，24h 审查 BUG-3/4/5/6 + L-11 核对）

> 背景：前端尚未设计（后端先行）。24h 审查报告中的"跨端契约待确认"项，
> 经用户拍板「前端等后端写差不多再写」后，由后端定稿作为前端实现的契约基准。
> 本文件是这些决策的唯一事实来源；前端开发时如有出入，以本文件为准并反馈。

## 1. 错误响应体（BUG-3 定稿）

- 全站统一 `ApiResponse{code, message, data}`，`code` 与 HTTP 状态码同值。
- **409 并发 Run 冲突**：`POST /student/chat` 同一会话已有活跃 Run 时返回 409，
  文案「会话 {sessionId} 已有活跃的 Run，无法创建新 Run」（ConcurrentRunException → 全局处理器）。
- **503**：数据库不可用（DataAccessException，文案「数据库暂时不可用，请稍后重试」）、
  消息队列暂不可用（XADD 失败）、文档解析队列繁忙（ETL 队列满快速失败，文案「文档解析队列繁忙，请稍后重试」）。
- 前端消费错误一律按 `code` 判断（等于 HTTP 状态码），不得依赖 `message` 文案。

## 2. null / [] 语义（BUG-5/6 定稿）

- **集合字段恒输出 `[]` 而非 `null`**：课程详情关联（contents/schedules/teacherIds 为空时）、
  消息 sourcesJson 等。前端遍历渲染无需判空。
- **可空对象字段恒输出 `null` 字段而非缺 key**：J4 分片上下文 parent/prev/next、
  J7 会话 lastMessageAt 等（MapStruct VO 恒输出全部字段）。前端用 `if (data.parent)` 判断即可。

## 3. token_count 语义（BUG-4 决策）

- `chat_message.token_count`：NULL（未统计）语义统一为 **0（计费为零）**——MP saveBatch
  不插入 null 列，DB DEFAULT 0 生效。当前无任何消费方（L-2 投影已丢弃该列）；
  未来做 token 用量统计时按「0 = 未统计」处理，不区分 NULL。

## 4. L-11 索引核对结论

- `pendingChunkCount`（correction_status=PENDING）：`idx_document_chunk_correction` ✓ 已有
- `studentCount`（role=STUDENT）：`idx_sys_user_role_status` ✓ 已有
- `feedbackStats/feedbackTrend`（created_at）：**原缺失** → 已补 V8 迁移
  `idx_user_feedback_created_at`（部分索引，deleted=0）

## 5. SSE `SOURCES` 事件 payload（B3-5 补记，2026-08-23）

SSE 10 事件（docs/plans/2026-07-16-frontend-design.md §1.6.4）中 `SOURCES` 此前未细化，
按实现定稿（载荷单元与 `record/RetrievalSource` 一致）：

```json
{"sources": [{"chunkId": "1234567890", "docTitle": "课程讲义第3章", "headingPath": "Ch3 > 3.2", "score": 0.87}]}
```

- **字段**：`chunkId`（分片唯一标识，B 端溯源）、`docTitle`（来源文档标题，PG
  document.title 回查填充，缺失为空串）、`headingPath`（文档内章节路径，可空串）、
  `score`（rerank 精排分数，0.0~1.0）。
- **发送时机**：`knowledge_question` 意图检索命中非空后，**首个回答 token 之前**推一次
  （每 run 至多一条）；`chat` / `unknown` 意图与空检索**不发**本事件
  （前端不得依赖每个 run 都收到 SOURCES）。
- **持久化对齐**：assistant 正文行 `chat_message.sources_json` 落同一 JSON 数组
  （无来源恒为 `[]`，见第 2 节 null/[] 语义）。

## 6. SSE `end` 事件 payload 扩展（2026-08-24 补口 B）

end 事件 payload 定稿为 `{runId, status, messageId}`：messageId 为 assistant
正文消息的雪花 ID 字符串（反馈接口必需）；仅 COMPLETED 状态携带，
CANCELLED/ERROR 与降级窗口为 null；前端按 `messageId?: string | null` 容忍。

## 7. Long 一律字符串序列化（2026-08-24 R0）

全工程 Long/long 字段（id/total/各计数/fileSize/learningCount 等）序列化为
JSON 字符串；Integer（page/size）与浮点（rating/score/likeRate/price）不受影响。
