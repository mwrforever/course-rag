## 〇、设计总纲

### 0.1 双端定位与设计读法

| 端 | 设计读法（one-line read） | 品味三档位 |
|---|---|---|
| C 端学生端 | 封闭私域「学习空间 × 课程橱窗 × AI 助教」消费级产品，面向学生，Clean Tech 暖调语言 | DESIGN_VARIANCE **6**（Bento 有节奏）/ MOTION_INTENSITY **5**（工作指示 + 状态过渡）/ VISUAL_DENSITY **4-5**（首页偏高、对话页低） |
| B 端管理后台 | 教师/超管的知识运维 cockpit，任务导向数据密集，Corporate Modern 语言 | DESIGN_VARIANCE **3**（可预测网格）/ MOTION_INTENSITY **2**（hover/active + spinner）/ VISUAL_DENSITY **8**（1px 分隔、mono 数字、极少卡片） |

### 0.2 全局硬性禁令（taste-skill 约束，两端通用）

1. **禁 Inter 作默认字体**；禁紫蓝 AI 渐变发光、neon 外发光、纯黑 `#000`、纯白 `#fff`。
2. **禁 3 等宽卡片横排**；列表用不对称网格 / Bento / 时间线等布局家族交替。
3. **禁 emoji 作 UI 图标**（v2 ASCII 稿里的 💻📚 一律换 Phosphor 线性图标）；emoji 仅允许出现在 AI 生成的正文 Markdown 中。
4. **禁 em-dash（—/–）出现在任何 UI 文案**；用逗号、句号、括号或普通连字符。
5. **每页一个 accent**（色锁）：C 端 teal、B 端 blue；语义色（success/danger/warning）只表达状态不作装饰。
6. **形状锁**（全站一套圆角规则，见各端 §形状系统）。
7. **动效动机化**：每个动画必须能用一句话回答"传达什么"（层级/叙事/反馈/状态迁移）；只动画 `transform`/`opacity`；`MOTION_INTENSITY > 3` 的全部动效在 `prefers-reduced-motion: reduce` 下降级为静态。
8. **常驻循环动画仅限"工作指示"**（打字光标、思考 shimmer、加载 spinner）；无装饰性无限动画。
9. 桌面优先（≥1280px 设计基准，两端均不做移动适配；多列布局在 <768px 收敛为单列兜底）。

### 0.3 工程结构约束（继承 v2 §0.1，任务重申）

- Monorepo 根目录下 `student-frontend/`（C 端）与 `frontend/`（B 端）**完全独立**：独立 package.json / node_modules / Tailwind / 组件配置。
- **禁共享包、禁跨项目 import**。两端唯一"共享"是运行时调用同一 Spring Boot 后端。
- 根 `package.json` 仅作聚合脚本（install / dev / build / test），用 pnpm workspace 管理。

## 一、C 端学生端设计系统（student-frontend/，Next.js + TS）

### 1.1 信息架构（基于后端现实收缩后）

```
用户旅程：登录 → 我的课程橱窗 → 课程工作台（资料+上下文）→ 问 AI 助教 → 反馈/会话管理

路由（App Router，全部 CSR；无公开接口故不做 SSR/ISR/SEO，见 §4 决策 D1）
/login                 登录页（(auth) 路由组，无顶导壳）
/                      首页：Hero + 我的课程 Bento 橱窗 + 最近会话 + 通用资料库入口
/courses               我的课程列表（J1 全量 + 本地 category 筛选 + 关键词过滤）
/courses/[id]          课程工作台：信息卡 + 资料分片列表（J2）+ 上下文抽屉（J4）+ AI 咨询 CTA
/chat                  新对话（sessionId=null 发起，metadata 事件后 replace URL）
/chat/[sessionId]      历史会话（依赖后端补口：会话历史消息接口，见 §4 决策 D2）
/sessions              会话管理（J6 分页列表 + J7 新建 + 时间分组）
/profile               个人中心（登录态信息 + 退出登录）
not-found.tsx          404
```

导航：**顶部固定导航 64px + 全宽内容区，无侧边栏**（与管理端彻底区分）。
- 左：Logo（几何渐变徽标）+ 品牌名「课程助手」；中：首页 / 我的课程 / 会话 / 个人中心（当前项 teal 短下划线 2px w-8）；右：头像下拉（displayName + 退出登录）。
- 对话页顶导保持在场（"回到平台"锚点），下加 40px 上下文条（返回课程 / 会话标题 / 新建对话）。

**SSE 10 事件 → UI 状态机**（payload 均源码实测）：

| 事件 | payload | 渲染动作 |
|---|---|---|
| metadata | `{runId, sessionId, model}` | 建 AI 消息槽；sessionId=null 发起时 `router.replace('/chat/'+id)`；记录 runId/model |
| thinking | `{delta}` | 思考卡展开，流式追加，指示灯旋转 + shimmer |
| thinking_end | `{}` | 思考卡折叠为摘要行（末句截断），高度过渡 240ms |
| delta | `{text}` | 正文流式追加 + Markdown 实时渲染 + 打字光标；智能吸底滚动 |
| tool_call | `{toolCallId, toolName, input}` | 插入工具卡 pending（spinner）；按 toolCallId 配对（空串容错） |
| tool_result | `{toolCallId, status, output}` | 工具卡转成功态 + 摘要 truncate；点击 popover 展示完整 output（mono） |
| sources | `{sources:[{chunkId,docTitle,headingPath,score}]}` | 来源卡组 stagger 滑入，置于正文之前；score 渲染为青色置信细条；每 run 至多一次，chat/unknown 意图没有（不得假设必有） |
| error | `{message?}` 或 `{message, code:"REPLAY_FAILED"}` | 消息尾错误横幅 + 分级操作（重试/重新提问）；解除输入禁用 |
| end | `{runId, status}` | COMPLETED→启用操作栏与反馈；CANCELLED→正文追加「已停止生成」后缀；解除输入禁用；只认首个终态（幂等） |
| `:heartbeat` | SSE 注释行 | fetch 解析器层重置 30s 断流计时器 |

**传输层**：POST + Authorization 头 → 必须 `fetch` + `ReadableStream` 手写 SSE 解析器（解析 `event:`/`data:`/`id:` 行与注释行）；每条事件存 `lastEventId`，断流时指数退避（1s/2s/4s，最多 3 次）调 `GET /chat/{runId}/reconnect?lastEventId=`。

**核心组件规范**：

- **ThinkingCard**：`surface-2 底 + 左侧 2px teal-300 竖线`，标题「正在思考…」→「已思考」，toggle 折叠；内容 13px/1.6 stone-500，max-h 200px 滚动。折叠态仅显示一行摘要。
- **SourcesList**：标题行「参考来源」+ 来源卡（文档图标 + docTitle + headingPath 双行 + score 置信条 0-1 青色填充）；点击复制片段文本（无跳转目标）。
- **ToolCallCard**：`inline-flex surface-2 rounded-xl px-3 py-2`；toolName 人话映射（如 searchKnowledge→「检索课程知识库」）；pending spinner / success 绿勾+摘要 / error 红叉；popover 显完整 JSON（mono 13px）。
- **消息操作栏**：hover/end 后 fade-in；复制（clipboard+toast）；反馈 👍/👎（Phosphor ThumbsUp/ThumbsDown，选中态 brand/红色填充，一次选择后锁定；messageId 来源依赖后端补口，见 §4 决策 D3）。
- **Markdown 渲染**：react-markdown + remark-gfm；代码块（语言标签 + 复制按钮 + 语法高亮 + 横向滚动）；表格（sticky 工具栏 + 复制）；任务清单/引用/分隔线全量支持；公式首版等宽文本回退（与 kimi 一致，KaTeX 列为后续机会）。用户消息纯文本渲染（防 XSS）。
- **输入区**：Enter 发送 / Shift+Enter 换行；空输入禁用发送；生成中发送键 morph 为停止键（`POST /chat/{runId}/cancel`，终态后 409 静默吞）；409 并发冲突 toast「当前会话正在回答中」。
- **附件**：＋ 按钮弹文件选择；前置校验镜像后端（≤10 个/次、图 ≤10MB[jpg/jpeg/png/gif/webp/bmp]、文档 ≤50MB[pdf/doc/docx/txt/md]、合计 ≤100MB）；选中即传 `POST /chat/attachments`，chips 显示进度；预览用本地 blob URL（返回 url 是 objectKey，非可访问 URL）；发送时 `attachments` 数组随 ChatRequest 提交。

#### 1.5.5 会话管理 `/sessions`

- H1 + [新建对话]（J7 创建后跳 `/chat/{id}`）。
- 列表项：会话标题（自动生成=query 前 30 字）+ status 徽章（ACTIVE/CLOSED）+ createdAt/lastMessageAt 相对时间；**时间分组**（今天/昨天/本周/更早）弥补无预览字段。
- 分页（J6 page/size=20）；删除/搜索依赖后端补口（§4 决策 D4），首版无删除入口。
- 空态：「还没有会话记录」+「开始对话」按钮。

#### 1.5.6 个人中心 `/profile`

- 用户卡：AI 徽标头像（displayName 首字母）+ displayName + username + role 徽章（登录响应缓存，见 §3.1）。
- 我的课程：复用 CourseCard（J1）。
- 退出登录：danger 文字按钮 → POST /auth/logout → 清理本地凭据 → 跳 /login。

## 三、通用规范（两端一致，实现细节各自独立）

### 3.1 认证交互（以后端源码实测为准，v2 §3.4 作废部分已修正）

- **登录**：`POST /api/v1/auth/login {username, password, deviceType:"WEB_DESKTOP"}` → `{accessToken, refreshToken, userId, role, displayName}`；AT 由后端同时写 httpOnly cookie（path=/，15min）。
- **凭据存储（C 端）**：AT 内存变量为主 + cookie 兜底（浏览器刷新后先尝试静默 refresh）；RT localStorage（key 带端前缀）。**R-4 决策：接受 RT localStorage 的 XSS 面**，理由：后端 RT 走响应体设计已定，仅内存方案刷新即丢登录体验不可接受；缓解：RT 7d 短时效 + 一次性旋转（被盗用即全量吊销）+ 无第三方脚本注入面。
- **凭据存储（B 端）**：RT sessionStorage（管理端安全要求更高，关浏览器即清）；AT 内存 + cookie。
- **请求封装**：统一 api client；401 → 单飞 refresh（`POST /auth/refresh {refreshToken}` body 传）→ 重放原请求；refresh 失败（含 RT 复用全量吊销）→ 清凭据 → 跳登录页 + toast「登录已失效，请重新登录」（**无 DEVICE_KICKED 专用码 G8/R-8，统一文案**）。并发 401 去重（共享一个 refreshPromise）。
- **路由守卫**：C 端 middleware（受保护：/chat、/sessions、/profile、/courses*、/；公开：/login）；B 端 beforeEach（公开仅 /login；meta.roles 校验，非授权 → /login?error=unauthorized 或 403 页）。B 端登录后校验 role ∈ {TEACHER, SUPER_ADMIN}，否则提示无权限不跳转。
- **登出**：POST /auth/logout（幂等）→ 清本地凭据 → 跳登录页。
- **SSE 期间 AT 过期**：发起 POST /chat 时 401 先静默刷新再重发；流建立后不受影响。

### 3.2 错误处理分级

| 场景 | 处理 |
|---|---|
| code===0 | 成功（**注意：成功码是 0 不是 200**） |
| 400 | 表单错误就地显示（zod 前置校验优先） |
| 401 | 全局拦截：静默刷新 → 失败登出跳登录 |
| 403 | C 端课程页专属引导态；B 端无权限页 |
| 404 | not-found 页 / 「资源不存在」 |
| 409（对话并发） | toast「当前会话正在回答中」 |
| 503 | toast/横幅「服务暂时不可用，请稍后重试」 |
| 网络错误 | toast「网络连接失败，请检查网络」不跳登录 |

集合恒 `[]` 直接遍历；可空对象字段恒 null 用 `if (x)` 判断（契约 §2）。

### 3.3 API client 契约

- baseURL `/api/v1`（dev 走 Vite/Next proxy 转发到 8080，规避 CORS；后端 CORS 白名单含 3000/3001/5173）。
- `credentials: 'include'`（AT cookie 兜底通道）。
- B 端 axios（DELETE 带 body 支持）；C 端 fetch 封装。

### 3.4 可访问性

## 六、二阶段对接修订（2026-08-24，消费 docs/backed/2026-08-24-后端功能调整.md）

以下修订以源码核查结论为准，覆盖本文件前文相应表述：

1. **TS 类型铁律**：后端补 Jackson Long→String 序列化（backed 文件 R0）后，**前端一切 id / total / fileSize 等 Long 来源字段按 `string` 接收**（TS 类型一律 string，禁止 number）；score/likeRate/rating 等浮点不受影响。§1.2/§2 中的字段类型描述据此理解。
2. **错误体特例**：AuthInterceptor 的 401 响应**无 data 键**（`{code,message}`），前端 ApiResponse 类型声明 `data?: T`。
3. **CORS/端口**：生效白名单为 **3000 与 5173**（3001 不生效）；B 端 dev server 必须固定 5173，或两端统一走本地 proxy 转发 8080（推荐，规避 CORS 与 cookie domain 问题）。
4. **SSE 部署注意**：响应未设 X-Accel-Buffering，经 nginx 反代部署时必须 `proxy_buffering off`（dev 直连无影响，列入部署清单）。
5. **时间格式**：LocalDateTime → ISO-8601 无时区串（`2026-08-24T10:15:30`），前端 `new Date(iso)` 按本地时区解析。
6. **补口落地后的能力增补**：
   - `GET /api/v1/student/sessions/{id}/messages`（backed R1）→ `/chat/[sessionId]` 历史回显：按行渲染（USER/ASSISTANT 正文行按消息流渲染；thinking/TOOL_CALL/TOOL_RESULT 行还原为思考卡/工具卡；sources 数组还原来源卡；attachments 还原用户附件 chips）。分页默认 size=200。
   - end 事件 payload `{runId, status, messageId}`（backed R2）→ 反馈按钮以 end.messageId 提交 J5；CANCELLED/ERROR 无 messageId（不展示反馈）。
   - `DELETE /api/v1/student/sessions/{id}`（backed R3）→ `/sessions` 列表项删除（二次确认；409「会话正在对话中」toast）。
7. **§1.5.5 修订**：删除入口从「首版无删除」升级为「随 R3 落地」；会话搜索仍不做（无消息内容搜索接口）。
8. **§1.5.4 修订**：sources 事件的 score 为 double（不受 R0 影响，number 类型）；SOURCES 事件与历史 sources 数组同构（RetrievalSource），TS 统一类型。
